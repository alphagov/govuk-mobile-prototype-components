# GOV.UK Mobile Prototype Components

Components for the GOV.UK app prototyping system: web components that look and behave like the GOV.UK app's own, so a prototype app journey can be built by writing HTML.

[PLAN.md](PLAN.md) says what the library is for and how we build it.

`src/` is the library, and everything in the package:

| Path | What it holds |
| --- | --- |
| [src/components/](src/components/) | One folder per component |
| [src/patterns/](src/patterns/) | Whole screens, arranged as the app arranges them, to copy and change the words of, each with when to use it and when not to |
| [src/templates/](src/templates/) | Real screens of the app, such as Settings, Home and Chat, as whole pages that link to each other, to copy and change to start a prototype. iOS only for now |
| [src/foundation/](src/foundation/) | What every component relies on: the app's tokens, the `<govuk-app>` root and `component.js` |
| [src/frame/](src/frame/) | `<govuk-prototype-frame>`, the iPhone around a prototype: its status bar and home indicator, fitted to the window. Not part of the app, so not a component |
| [src/schemas/](src/schemas/) | What a component's, pattern's and template's definition must say |

Around it:

| Path | What it holds |
| --- | --- |
| [examples/](examples/) | Screens of the app built from the components alone, such as Home and Settings, to see them working together. Not prototypes to build on |
| [docs/](docs/) | The documentation site |
| [scripts/](scripts/) | The catalogue and the screenshots |
| [inventory/](inventory/COMPONENTS.md) | Every component in the iOS and Android apps today, with screenshots. The backlog |
| `catalogue/` | Every pattern, template and component, for tools that build prototypes: a short index, a card for each, and all of it as data in `catalogue.json`. Generated by `npm run catalogue`, and in the package, but not committed |

The docs site publishes `src/` at the same paths, so a link that works in the repository works on the site.

Documentation: <https://alphagov.github.io/govuk-mobile-prototype-components/>, with every component drawn live in light and dark beside the app's own screenshots.

## Make a prototype

Designers can make a prototype of the GOV.UK app by asking [Claude Code](https://code.claude.com/docs/en/overview), with the plugin in [`plugin/`](plugin/).

While this repository is private, they first need a GitHub account with access to it, and their computer signed in to GitHub: for example with GitHub's `gh` tool, `gh auth login` then `gh auth setup-git`, which Claude can do for them. Adding the plugin and installing the components both read from here.

Then add it once, in Claude Code:

```text
/plugin marketplace add alphagov/govuk-mobile-prototype-components
/plugin install govuk-app-prototyping@govuk-app
```

Then, in an empty folder, say "Make a new prototype of the GOV.UK app". Claude asks for a name and where to start (Home, Settings, Chat or a blank screen), gets the computer ready, asking before it installs anything, and opens the prototype in the browser. Next time, "Open my prototype". It's on the computer only, and iOS only, for now.

Your organisation's managed Claude Code settings may not allow adding plugin marketplaces. If adding it fails, ask whoever runs your setup to allow this repository.

See [Make a prototype](docs/get-started/make-a-prototype.md) for more, and [`plugin/starter/`](plugin/starter/) for what a new prototype is made of.

## Running the docs locally

You need Node.js 26, the version in `.nvmrc` (`nvm use` picks it up). Anything from 22.16 works.

```sh
npm install
npm start
```

Then open <http://localhost:8080>. The site reloads when you change a component, its definition, or a page.

`npm run build` builds the site into `_site/`. It fails if any component's definition doesn't match [`src/schemas/component.schema.json`](src/schemas/component.schema.json), or any pattern's [`src/schemas/pattern.schema.json`](src/schemas/pattern.schema.json). It writes the catalogue first, and fails if a component isn't in one of its index's groups.

The site is built with the [GOV.UK Eleventy Plugin](https://github.com/x-govuk/govuk-eleventy-plugin), and published to GitHub Pages from `main` by [`.github/workflows/docs.yml`](.github/workflows/docs.yml). Its source is in `docs/`:

| Path | What it holds |
| --- | --- |
| `docs/*.md`, `docs/get-started/` | Pages of prose. Add a Markdown file to add a page |
| `docs/_data/components.js` | Reads and checks every `src/components/<name>/<name>.json` |
| `docs/components/component.njk` | Draws a page for each component from its definition |
| `docs/_data/patterns.js` | Reads and checks every `src/patterns/<name>/<name>.json`, and that its HTML uses only the library's components |
| `docs/patterns/pattern.njk` | Draws a page for each pattern from its definition and HTML |
| `docs/eleventy.config.js` | The site's configuration |

Only the docs have a build step. The components don't: the site copies `src/components/`, `src/foundation/` and `src/frame/` as they are.

## Checking what a component looks like

`npm run screenshots` draws every component's examples, and every page in `examples/`, in light and dark, in a headless Chromium, so you can see them without a browser. It builds the site first, and serves it itself.

The first time, install the browser it draws with:

```sh
npx playwright install chromium
```

Then:

```sh
npm run screenshots                          # everything
npm run screenshots -- button                # one component's examples
npm run screenshots -- --examples            # only the pages in examples/
npm run screenshots -- --url /examples/settings/index.html   # any page of the site
npm run screenshots -- button --no-build     # use the site already in _site/
```

They go in `screenshots-out/`, which git ignores: `<component>/<example>-light.png` and `-dark.png`, `examples/…`, and `pages/…` for `--url`. Open `screenshots-out/index.html` to see each component's screenshots beside the app's own, from its `reference/` folder.

## Using a component

Load the component's script, and write its element inside a `<govuk-app>`:

```html
<script type="module" src="src/components/button/button.js"></script>

<govuk-app>
  <govuk-app-button name="continue">Continue</govuk-app-button>
</govuk-app>
```

See [Get started](docs/get-started/index.md) for more.

## Using it in another project

Install it from GitHub, at a tag or commit, so it changes only when you choose:

```sh
npm install github:alphagov/govuk-mobile-prototype-components#<tag or commit>
```

Then serve `node_modules/govuk-mobile-prototype-components/` with your pages, and load each component's script from there. The components load their templates, styles and fonts from beside their scripts, and nothing from anywhere else, so they work under a strict Content Security Policy and offline.

The package has the components, the foundation and the frame, and none of the app's screenshots, which are only for this repository's docs.

## A component

Each component is one folder, `src/components/<name>/`, holding its template (`.html`), styles (`.css`), element (`.js`), definition (`.json`), an optional `.md` of prose for its page, and the app's screenshots in `reference/`. Every folder with a definition gets a page on the site, with no list to update.

See [Build a component](docs/get-started/building-a-component.md) for how they work and how to add one.

## A pattern

A pattern is one of the app's screens, put together from the components: a folder, `src/patterns/<name>/`, holding its HTML (`<name>.html`, one `<govuk-app-screen>` and what's in it) and its definition (`<name>.json`, following `src/schemas/pattern.schema.json`). The definition says what it's for, when to use it, when to use another pattern instead, the components it uses and which of the app's screens it's taken from, so a person or a tool can choose between patterns. Every folder with both gets a page on the site.
